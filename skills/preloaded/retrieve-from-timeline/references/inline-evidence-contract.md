# 视频内联引用契约 v1

仅在用户要求视频定位、时间点、视频溯源，或回答需要把视频证据嵌入正文时读取本文件。

能力标识：`video_evidence_citation/v1`

## 能力声明

支持该能力的智能体必须声明：

```yaml
video_evidence_citation: v1
```

声明只表示智能体可以消费平台提供的视频证据上下文，不表示智能体可以自行生成视频 ID、证据 ID 或时间。

## 目标

让回答正文中的视频证据可被前端安全地渲染为：

```text
「03:12–03:48」讲解提示词公式。
```

## 模型输出协议

- 只使用系统提供且出现在当前上下文中的 `<ref id="cN"/>`。
- 将引用紧跟在其支持的主张后面，并与主张保持同一行。
- 不要在 `<ref>` 前单独重复视频标题、时间范围或“视频来源：”标签；标题和时间由系统统一投影。
- 不输出 `<kb>` / `<web>` 标签、Markdown 视频链接，不拼接视频地址，不创建新的视频 ID、证据 ID 或时间。

`<ref>` 是模型侧协议。系统在后端完成白名单校验后，会将合法引用转换为前端既有的来源标签；模型不需要也不允许感知这一步。

示例：

```text
提示词公式（角色 + 任务 + 要求 + 格式）见 <ref id="c1"/>。
```

前端根据问题语义和会话上下文把上面的句柄投影为以下之一：

```text
提示词公式（角色 + 任务 + 要求 + 格式）见「03:12–03:48」。
```

需要区分多个视频来源时才显示视频名称：

```text
提示词公式（角色 + 任务 + 要求 + 格式）见《AI提示词是什么？怎么写AI提示词？为什么别人用ai生成的内容比自己好？》「03:12–03:48」。
```

## 证据结构与校验

可点击视频引用必须同时具备：

- `video_id`：目标视频身份；
- `video_title`：用户可见视频标题；
- `start_ms`、`end_ms`：同一证据片段的起止时间，且 `end_ms > start_ms`；
- `evidence_sentence_id`：可回溯的证据句柄；
- `transcript_generation`：当前有效的转写代次；
- `linkable`：证据通过全部校验后才为 `true`。

后端只接受当前检索上下文中的证据 ID，并重新核对视频身份、转写代次和时间范围。模型输出的时间、视频 ID 或证据 ID不作为可信来源。

来源为 Wiki 页面但没有对应视频转写证据时，只保留普通来源引用。

定位型回答应优先引用当前转写分块；Wiki 页面可以提供知识对象的解释，但不能单独证明视频中的时间位置。

## 前端投影

后端校验引用并补充视频定位数据，前端再将引用投影为时间段：

- 当前视频且来源已由会话上下文明确时显示 `「开始时间–结束时间」`；用户要求区分视频或来源不唯一时显示 `《视频标题》「开始时间–结束时间」`；开始和结束时间都来自同一条证据；
- 当前视频：定位播放器到开始时间；
- 其他视频：进入对应视频详情页，并定位到开始时间；
- 默认只定位，不自动播放；
- 时间相同的不同视频必须通过视频 ID区分，不能按时间反查视频。

## 多视频与多时间段

- 按视频分组，组内按开始时间排序。
- 同一视频相邻证据可合并为一个时间范围。
- 每个时间段绑定自己的视频 ID和证据句柄。

## 失败与降级

引用校验失败时使用以下内部原因之一：

| 原因 | 处理 |
|---|---|
| `invalid_handle` | 丢弃无效引用 |
| `evidence_out_of_scope` | 丢弃不属于本次上下文的证据 |
| `missing_video` | 不生成视频定位 |
| `missing_time_range` | 不生成视频定位 |
| `generation_mismatch` | 不生成视频定位 |
| `wiki_only_source` | 保留普通 Wiki 来源 |
| `unpublished_evidence` | 证据尚未完成发布，保留普通来源但不可定位 |

用户侧统一降级为普通文字，并说明时间未验证。不得估算时间、拼接链接或生成不可验证的按钮。失败不能覆盖已有的有效回答或已发布结果。

## 稳定性门禁

- 能力版本、引用协议和前端投影协议必须保持同一版本。
- 新智能体只有在通过公共契约测试后才能声明支持该能力。
- 任何新智能体的自定义提示词不得修改 `<ref>` 语法和证据字段语义。
- 未来协议升级必须新增版本并保留旧版本的读取兼容，不直接改变 `v1` 的含义。
